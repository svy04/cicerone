# 화두 (hwadu)

한국 채용 공고를 평가하고 지원 서류를 준비하는 명령줄 도구입니다. 클로드 코드나 코덱스 같은 인공지능 명령줄 도구 안에서 돌아가고, 파일은 전부 내 컴퓨터에 남습니다.

[한국어](README.md) | [English](README.en.md)

- **공채와 수시를 갈라서 봅니다.** 전형 순서도 필요한 서류도 다르기 때문에, 평가 첫 단계가 이 판정입니다
- **자기소개서를 문항별로 씁니다.** 회사가 정한 문항과 글자 수에 맞춰 초안을 만들고, 어느 경험을 근거로 썼는지와 고쳐 쓰면 좋은 자리를 함께 표시합니다
- **제시받은 연봉을 분해합니다.** 퇴직금이 들어 있는지, 고정 초과근로수당이 몇 시간분인지, 성과급을 미리 넣었는지를 묻습니다
- **경력기술서를 따로 만듭니다.** 경력 지원의 본문이고, 이력서와 다른 문서입니다
- **필기 전형을 관문으로 다룹니다.** 인적성검사와 코딩테스트가 서류와 면접 사이에 있습니다
- **채용절차법이 금지한 항목**을 공고가 요구하면 알려 줍니다
- **지원한 곳을 한 파일에 모읍니다.** 채용 사이트마다 갈라지지 않습니다

```
$ node salary-korea.mjs offer 52000000 --퇴직금포함 --고정OT 20

제시받은 연봉    52,000,000원
확실한 금액      48,000,000원

분해
  · 퇴직금이 포함된 제시액입니다. 통상 방식대로 나누면 실제 급여는 약 48,000,000원이고
    나머지가 퇴직금 적립분입니다. 퇴직금은 1년 이상 근무해야 발생합니다.
  · 고정 초과근로 20시간분이 급여에 들어 있습니다. 그만큼 일하지 않아도 받지만,
    반대로 그 시간까지는 야근해도 추가 수당이 없습니다.

아직 확인 못 한 것 — 처우 협의에서 물어보세요
  ? 성과급이 제시액에 포함됐는지 별도인지 확인하지 않았습니다
```

## 시작하기

Node.js 22 이상이 필요합니다. 인공지능 명령줄 도구를 쓰고 있다면 대개 이미 깔려 있습니다. `node -v` 로 확인하고, 없거나 낮으면 [nodejs.org](https://nodejs.org)에서 받습니다.

**1. 받습니다.**

```bash
git clone https://github.com/svy04/hwadu.git
cd hwadu
npm install
```

윈도에서 파워셸을 쓴다면 아래 문서의 `cp` 를 `copy` 로 바꿔 읽으세요. 깃 배시를 쓰면 그대로 됩니다.

**2. 이 폴더에서 인공지능 명령줄 도구를 엽니다.**

```bash
claude          # 또는 codex, opencode 등 쓰는 것
```

**여는 위치가 중요합니다.** 방금 클론한 `hwadu` 폴더 안에서 열어야 `/hwadu` 명령이 잡힙니다. 다른 폴더에서 열면 이 저장소의 지시문을 못 읽습니다.

**3. 준비가 됐는지 봅니다.**

```bash
node doctor.mjs
```

무엇이 빠졌는지 알려 줍니다. 아직 설정 파일이 없다고 나오는 것이 정상입니다.

## 준비하기

설정 파일 하나와 이력서 하나가 필요합니다.

```bash
cp config/profile.example.yml config/profile.yml
cp examples/cv-example.md cv.md
```

`config/profile.yml`을 열어 채웁니다. 신입인지 경력인지, 어떤 직무를 보는지, 연봉 기준선이 얼마인지를 적습니다.

```yaml
target:
  career_stage: "경력"
  years: 5
  roles:
    - "백엔드 개발자"
  track: "수시"        # 공채 | 수시 | both
```

**이름은 두 곳에 있습니다. 둘 다 고치세요.** `config/profile.yml` 의 `candidate` 와 `cv.md` 첫 줄입니다. 한쪽만 고치면 만들어진 이력서에 예시 이름이 섞여 나갑니다.

```yaml
candidate:
  name: "홍길동"
  email: "gildong@example.com"
  phone: "010-0000-0000"
  location: "서울 강남구"
```

연봉 기준선도 같이 적습니다. 단위는 만 원입니다.

```yaml
compensation:
  target: 7000      # 세전 계약 연봉 기준
  minimum: 6000     # 이 아래로는 안 간다는 선
```

경력 지원이면 경력기술서를 함께 만들지도 여기서 정합니다. 예시 파일에는 켜져 있습니다.

```yaml
documents:
  career_description: true
```

**여기까지가 필수입니다.** 나머지 칸은 비워 둬도 돌아갑니다. 예시 파일의 주석을 읽고 필요할 때 켜세요.

`cv.md`에는 이력을 마크다운으로 적습니다. 지금까지 쓰던 이력서를 붙여넣고 다듬어도 됩니다. 형식이 막막하면 `examples/cv-example.md` 를 보세요. 최소한 아래는 있어야 합니다.

```markdown
# 홍길동
백엔드 개발자 · 5년

## 경력
### 어느회사 (2021-03 ~ 재직 중) — 백엔드 개발자
- 결제 정산 시스템을 다시 만들어 지연 건수를 월 300건에서 5건으로 줄였습니다
- ...

## 기술
Java, Spring, Kotlin, MySQL, Kafka
```

## 공고 평가하기

`hwadu` 폴더에서 연 인공지능 명령줄 도구에, 공고 주소를 이렇게 붙여넣습니다.

```
/hwadu https://kakaopay.career.greetinghr.com/ko/o/206749
```

**어느 사이트 공고든 주소를 붙여넣는 것은 언제나 됩니다.** 사람인이든 잡코리아든 원티드든 상관없습니다. 사람이 브라우저로 여는 것과 같은 일이기 때문입니다. 아래 「공고 모으기」의 제약은 **자동으로 대량 수집할 때** 이야기입니다.

먼저 공고가 아직 열려 있는지 확인하고, 공채인지 수시인지 판정한 뒤, 일곱 블록으로 평가합니다.

| 블록 | 보는 것 |
|---|---|
| A | 자리 요약 — 트랙, 고용 형태, 근무 형태, 채용절차법 위반 여부 |
| B | 이력서와 얼마나 맞는지, 모자란 부분은 무엇인지 |
| C | 요구 연차와 내 연차, 직급 표기 |
| D | 연봉 — 무엇이 포함됐는지, 시세는 어느 수준인지 |
| E | 서류 준비 계획 (트랙에 따라 다름) |
| F | 전형 대비 계획 (트랙에 따라 다름) |
| G | 실제로 사람을 뽑는 공고인지 |

평가 내용은 화면에도 보이고 파일로도 남습니다.

```
reports/001-카카오페이-2026-08-21.md   ← 평가 전문
data/applications.md                    ← 지원 현황 표에 한 줄 추가
```

보고서 첫머리는 이렇게 생겼습니다.

```markdown
# 카카오페이 — 서버 개발자, 결제 서비스

**점수:** 4.3/5
**트랙:** 수시
**URL:** https://kakaopay.career.greetinghr.com/ko/o/206749

## Block A — 자리 요약
| 항목 | 내용 |
|---|---|
| 채용 트랙 | 수시 |
| 고용 형태 | 정규직 |
| 경력 요건 | 3년 이상 (공고 표기 그대로) |
| 근무 형태 | 하이브리드 — 주 3회 출근 |
...
```

## 공고 여러 개 모으기

주소를 하나씩 붙여넣는 대신, 관심 있는 회사들의 채용 페이지를 한 번에 읽을 수 있습니다.

```bash
cp templates/portals.korea.example.yml portals.yml
node scan.mjs
```

`portals.yml`에 적은 회사만 읽습니다. 결과는 `data/pipeline.md`에 쌓이고, 거기서 골라 평가하면 됩니다.

### 수집할 때 지키는 넷

이 도구는 채용 포털과 기업 채용 페이지에서 공고를 읽습니다. 읽는 방식에 규칙을 뒀습니다.

1. **정체를 밝힙니다.** 도구 이름이 들어간 사용자 에이전트를 씁니다. 브라우저인 척하지 않습니다
2. **robots.txt를 봅니다.** 막아 둔 경로는 건드리지 않습니다. 인크루트와 링크드인은 모든 봇에게 전면 금지라 아예 대상에서 뺐습니다
3. **원문 주소를 남깁니다.** 공고를 어디서 가져왔는지 항상 보존합니다
4. **재배포하지 않습니다.** 읽은 공고는 당신 컴퓨터에만 남습니다. 서버로 올리지도, 다른 사람에게 넘기지도 않습니다

이 넷은 임의로 정한 것이 아닙니다. 잡코리아와 사람인의 공고 수집 분쟁 1심(서울중앙지법 2015가합517982)이 **정상적인 수집과 문제가 된 수집을 가른 기준**이 이것이었습니다. 그 사건에서 문제가 된 것은 경쟁 채용 사이트가 남의 공고를 긁어 **자기 사이트에 올린 것**이었습니다. 야놀자와 여기어때 사건도 경쟁 숙박 앱이 제휴 업소 정보를 **자기 서비스에 쓴 것**이 쟁점이었습니다.

개인이 자기 구직을 위해 공개된 공고를 읽는 것과, 경쟁 서비스가 남의 데이터베이스를 자기 영업에 쓰는 것은 다른 일입니다. 이 도구는 앞쪽입니다.

### 어디서 읽나

| 곳 | 읽는 방식 | 알아 둘 것 |
|---|---|---|
| 사람인 | 공개 검색 결과 페이지 | 검색어나 지역 중 하나는 넣어야 시작합니다. 조건 없이 전체를 훑지 않습니다 |
| 잡코리아 | 직무·지역·업종 목록 탭 | robots.txt가 키워드 검색을 막아 둬서, 키워드는 받아 온 목록에 대고 내 컴퓨터에서 거릅니다 |
| 점핏 | 개발 직군 목록 | 기술 스택과 경력 범위가 목록에 함께 옵니다 |
| 리멤버 커리어 | 사이트맵에서 번호를 얻고 공고를 하나씩 | 여기만 요청이 공고 수만큼 늘어납니다. 25건에 약 30초 |
| 그리팅을 쓰는 기업 | 회사 채용 페이지 | `portals.yml`에 적은 회사만 읽습니다 |
| 고용24 (옛 워크넷) | 공개 API | 인증키를 본인 명의로 받아야 합니다. 공공기관·지자체 채용과 중소기업 공고가 여기 많습니다 |

원티드는 뺐습니다. 도구 이름을 밝힌 요청은 robots.txt를 포함해 모든 경로가 앞단에서 403으로 끊깁니다(2026년 8월 21일 확인). 둘째 규칙을 지키려면 robots.txt를 봐야 하는데 그 파일부터 못 받습니다. 브라우저인 척하면 열리지만 그건 첫째 규칙을 버리는 일입니다. 원티드 공고는 주소를 붙여넣어 한 건씩 평가합니다.

**사람인 공개 API도 쓸 수 있습니다.** [이용 신청](https://oapi.saramin.co.kr/join)에서 본인 명의로 열쇠를 받아 환경변수 `SARAMIN_ACCESS_KEY`에 넣으면 됩니다. 하루 500회 제한이 있고, 받은 데이터를 되팔 수 없습니다. 열쇠가 없어도 페이지를 읽는 방식으로 동작합니다.

## 코덱스로 쓰기

클로드 코드가 아니라 코덱스(Codex)를 쓴다면 슬래시 명령이 그대로 통하지 않을 수 있습니다(slash commands are not guaranteed there). 그럴 때는 평문으로 시킵니다 — 명령 이름을 문장 안에 넣은 prompt 를 그대로 주면 됩니다.

```bash
codex exec "hwadu auto-pipeline 으로 이 공고를 평가해 줘: https://company.com/jobs/123"
```

코덱스에서 설정하는 방법과 주의점은 [docs/CODEX.md](docs/CODEX.md)에 있습니다.

## 서류 준비하기

수시 지원이면 이력서와 경력기술서를 만듭니다.

```
/hwadu pdf 카카오페이
```

**회사 이름 자리에는 평가할 때 쓴 이름을 그대로 넣습니다.** `reports/` 에 생긴 파일 이름을 보면 됩니다(`001-카카오페이-2026-08-21.md` 라면 `카카오페이`). 보고서 번호로 불러도 됩니다.

공고를 평가하지 않고 이력서만 만들 수도 있습니다. 그때는 공고 본문을 붙여넣으라고 물어봅니다.

결과는 이렇게 남습니다.

```
output/cv-홍길동-카카오페이.pdf                  ← 이력서
output/cv-홍길동-카카오페이.html                 ← 고칠 수 있는 원본
output/career-description-홍길동-카카오페이.pdf  ← 경력기술서 (스위치가 켜져 있을 때)
```

경력기술서는 `documents.career_description: true` 일 때 함께 만듭니다. 따로 만들려면 `/hwadu career-description 카카오페이` 를 씁니다.

HTML을 손으로 고쳤다면 `node generate-pdf.mjs output/cv-홍길동-카카오페이.html` 로 다시 뽑습니다.

PDF를 만들 때 브라우저 엔진을 씁니다. `npm install` 이 알아서 깔지만, 실패하면 `npx playwright install chromium` 을 한 번 실행하세요.

이력서는 두 장 안팎으로 만듭니다. **공고에 나온 단어를 이력서에 억지로 넣지 않습니다.** 한국 채용 시스템이 키워드로 서류를 자동으로 거른다는 근거를 찾지 못했고, 미국 조언을 그대로 옮겨 오면 사람이 읽기 나쁜 이력서만 남습니다.

공채 지원이면 자기소개서 문항을 정리합니다.

```
/hwadu cover 삼성전자
```

문항이 무엇을 묻는지 풀어 주고, 이력에서 그 문항에 쓸 경험을 찾아 짝지어 주고, 어떤 순서로 몇 자씩 쓸지 제안합니다. **거기까지입니다.** 초안을 써 오면 이력과 어긋나는 사실을 찾아 주고 글자 수를 세어 줍니다.

## 자기소개서를 쓸 때 알아 둘 것

초안은 만들어 드립니다. 그 위에 알아 둘 사실이 하나 있습니다. **한국 기업 일부는 자기소개서에 인공지능을 썼는지 검사합니다.**

- 2025년 하반기 공채를 진행하는 10대 그룹 계열사와 공기업 14곳 중, 인공지능을 도입한 10곳 가운데 9곳이 서류전형에서 표절률을 확인했습니다 (연합뉴스, 2025-09-29)
- 인공지능으로 쓴 것이 확인되면 감점하겠다는 답이 42.2%, 불합격시키겠다는 답이 23.2%였습니다 (고용노동부·한국고용정보원 「2023년 하반기 기업 채용동향조사」, 매출 500대 기업 315개소)
- 국민연금공단은 2025년 9월 신입 서류접수 공고에 "AI(챗-GPT 등) 활용 및 표절 여부 등을 철저히 검증할 예정"이라고 적었습니다

**그래서 초안을 그대로 내기보다 본인 말로 고쳐 쓰기를 권합니다.** 문체가 균질하면 눈에 띄고, 면접에서 자기 문장이 아닌 것을 설명하기 어렵습니다. 도구가 고쳐 쓸 자리를 표시해 주니 거기부터 손대면 됩니다. 이 안내는 한 번만 하고 매번 반복하지 않습니다.

**탐지를 피하는 기능은 만들지 않습니다.** 문체를 흩뜨려 검사를 속이는 방식은 걸렸을 때 더 나쁩니다. 대신 재료를 정확히 찾고 사실을 맞추는 데 힘을 씁니다.

**없는 경험은 쓰지 않습니다.** 초안은 이력서와 경력 기록에 있는 사실로만 만듭니다. 면접에서 자기소개서 문장을 근거로 꼬리질문이 들어오는데, 지어낸 경험은 그 자리에서 무너집니다.

## 전형 준비하기

필기 전형이 있으면 남은 날짜를 역산해 계획을 만듭니다.

```
/hwadu written-test 삼성전자
```

면접은 트랙에 따라 갈립니다. 공채는 자기소개서 문장마다 나올 꼬리질문을 만들고, 수시는 이력서에 적은 프로젝트마다 나올 심층 질문을 만듭니다.

```
/hwadu interview-prep 카카오페이
```

## 내 정보는 어디까지 가나

**만들어진 파일은 전부 내 컴퓨터에 남습니다.** 이 도구는 서버를 두지 않고 계정도 요구하지 않습니다. 수집한 공고를 어디로도 올리지 않습니다.

다만 **평가와 서류 작성은 인공지능 모델이 합니다.** 그러려면 이력서와 공고 본문이 쓰고 있는 명령줄 도구를 거쳐 모델 제공자에게 전달됩니다. 클로드 코드를 쓰면 앤트로픽으로, 코덱스를 쓰면 오픈에이아이로 갑니다. 이 도구가 그 경로를 만드는 것이 아니라, 이미 쓰고 있는 도구의 경로를 그대로 탑니다.

연락처와 연봉 기준선이 설정 파일에 들어가므로, 그 정보도 평가할 때 함께 읽힙니다. 넣기 싫은 항목은 비워 두면 됩니다 — 이름과 이메일만 있어도 돌아갑니다.

## 밝혀둘 것 세 가지

**국내 채용 관리 시스템 중 전용 모듈이 있는 곳은 그리팅 하나입니다.** 나인하이어와 잡다는 로그인 없이 읽을 수 있는 공고 목록을 확인하지 못했습니다. 그 회사들의 공고는 주소를 직접 붙여넣어야 합니다.

**시장 사실은 2026년 8월 21일에 확인한 것입니다.** 사회보험 요율, 소득세 구간, 공채 일정, 채용 플랫폼의 약관은 해마다 바뀝니다. 각 주장의 출처와 확인 시점은 [docs/market-evidence.md](docs/market-evidence.md)에 있고, 근거를 찾지 못한 항목도 그렇게 적혀 있습니다.

**실수령액 계산은 추정입니다.** 부양가족과 세액공제에 따라 달라지고, 매달 떼는 금액은 간이세액표를 따르며 최종 금액은 연말정산으로 정산됩니다. 계약서를 대신할 수 없습니다.

## 해외 지원

외국계나 해외 기업에 지원한다면 `modes/global/`에 영어판 규격이 그대로 있습니다. 비자 후원 검사, 미국 주별 급여 공개법, 인력업체 면허 신호처럼 그쪽에서 필요한 것들이 남아 있습니다.

## 왜 화두인가

화두는 스승이 답을 주지 않고 질문 하나를 건네는 방식입니다. 답은 받는 사람이 스스로 뚫습니다.

이 도구가 자기소개서 문항을 대하는 방식이 그렇습니다. 회사가 던진 문항을 풀어 주고, 그 문항에 쓸 경험을 찾아 주고, 어떤 순서로 몇 자씩 쓸지 잡아 줍니다. 문장은 쓰는 사람이 씁니다.

대신 써 주는 도구는 이미 많습니다. 이 도구는 그 반대편에 서 있습니다.

## 어디서 왔나

[santifer/career-ops](https://github.com/santifer/career-ops)에서 갈라져 나왔습니다. 원본은 미국 취업 시장을 전제로 만들어졌고, 이 저장소는 그 전제를 한국 기준으로 바꿨습니다. 무엇이 어떻게 바뀌었는지는 [docs/korea-fork.md](docs/korea-fork.md)에 적었습니다.

지원 현황 추적, 서류를 만드는 내부 처리, 스스로 갱신하는 기능, 시험 4,900여 건은 원본 것을 그대로 씁니다.
