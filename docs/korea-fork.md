# 한국판 전환 — 원본에서 무엇이 바뀌었나

이 저장소는 [svy04/cicerone](https://github.com/svy04/cicerone)에서 갈라져 나왔습니다. 원본은 미국 취업 시장을 전제로 설계됐고, 이 저장소는 그 전제를 한국 시장 기준으로 바꿨습니다.

원본을 알고 오신 분을 위해 무엇이 살아 있고 무엇이 바뀌었는지 적습니다. 모든 시장 사실의 출처는 `docs/market-evidence.md`에 있습니다.

## 한 줄 요약

원본의 배관은 그대로 쓰고, 사용자가 만나는 표면은 거의 전부 바꿨습니다. 평가 기준, 지원 서류, 전형 대응, 협상, 공고 수집 경로가 모두 다릅니다.

## 왜 번역이 아니라 전환인가

원본에도 `modes/ko/` 한국어 번역이 있었습니다(이 저장소에서는 지웠습니다 — 아래 이유 때문입니다). 포괄임금제·퇴직금·4대 보험 같은 용어표까지 갖췄습니다. 그런데 그 아래 골격은 미국판 그대로였습니다.

- 직무 유형 여섯 가지가 원저자 개인의 인공지능 커리어에 고정돼 있었습니다
- 공고 수집 모듈 85개 중 한국 채용 소스는 하나도 없었습니다
- 비자 후원 검사, 채용 시스템 키워드 통과 전략, 여러 제안을 경쟁시키는 협상법이 그대로 있었습니다
- 신입 공채, 자기소개서 문항, 인적성검사, 코딩테스트, 경력기술서처럼 한국 전형의 핵심이 규격에 없었습니다

문장은 한국어인데 규격은 미국판이었습니다. 이 저장소는 그 규격을 바꿨습니다.

## 미국 전제 중 뺀 것

### 이력서 키워드로 자동 심사를 통과한다는 전략

**한국에서 이 전략이 유효하다는 근거를 찾지 못했습니다.** 국내 채용 관리 시스템의 공개 설명은 지원자 관리와 평가 협업이고, 이력서를 키워드 매칭으로 자동 탈락시킨다는 기술 문서가 없습니다.

한국에서 실제로 돌아가는 자동 심사는 다른 것입니다. **자기소개서 표절과 인공지능 작성 탐지**입니다. 2025년 하반기 공채에서 인공지능을 도입한 대기업·공기업 10곳 중 9곳이 서류전형에서 표절률을 확인했습니다.

그래서 이 저장소는 키워드 주입 기능을 뺐습니다. 자기소개서는 문항마다 초안을 만들되, **검사가 돌아간다는 사실을 한 번 알리고 고쳐 쓸 자리를 표시**합니다. 문체를 흩뜨려 검사를 속이는 기능은 만들지 않습니다.

### 비자 후원 신호

한국 구직자가 한국 기업에 지원하는 상황에는 해당하지 않습니다. 해외·외국계 지원용으로 `modes/global/`에 그대로 보존돼 있습니다.

### 미국·캐나다 관할의 법률 신호

인력업체 면허, 뉴욕시 인공지능 심사 고지 조례, 미국 주별 급여 공개법, 최저임금 환산, 이민 신분 요구 과잉 — 관할이 다릅니다. 한국에는 **채용절차법 제4조의3** 검사가 그 자리를 대신합니다.

이 신호들도 `modes/global/`에 남아 있고, 원본 시험도 그 파일을 보도록 옮겼습니다. 검사를 지운 것이 아니라 대상을 옮긴 것입니다.

### 한 장짜리 이력서

한국 통념은 두 장 안팎이고, 경력기술서를 포함해 네 장까지입니다.

### 여러 회사의 제안을 경쟁시키는 협상

한국에서 효과가 측정된 적이 없습니다. 실무 증언이 양쪽으로 갈리고, 사내 급여 구간과 기존 직원 형평이 상한을 만든다는 서술이 반복됩니다. 권하지도 말리지도 않고 근거가 없다는 사실만 알립니다.

## 새로 만든 것

### 채용 트랙 판정

한국의 채용은 **공채**와 **수시** 두 갈래로 갈리고, 갈래마다 필요한 산출물이 완전히 다릅니다. 평가의 0단계가 이 판정입니다. 이것을 건너뛰면 나머지가 전부 어긋납니다.

### 문항형 자기소개서 (`modes/cover.md`)

원본의 커버레터 생성기를 대체합니다. 회사가 문항과 글자 수를 정해 주기 때문에 영어 커버레터와 구조가 다릅니다. 문항별로 초안을 쓰고 근거가 된 경험을 함께 냅니다.

### 경력기술서 (`modes/career-description.md`)

원본에 대응물이 없습니다. 한국 경력 채용의 본문입니다.

### 필기 전형 (`modes/written-test.md`)

인적성검사와 코딩테스트가 서류와 면접 사이에 놓입니다. 원본에는 이 단계가 없습니다. 지원 추적에도 `Written` 상태를 새로 만들었습니다.

### 급여 분해기 (`salary-korea.mjs`)

한국에서 "연봉"은 법률 용어가 아니라 관행어입니다. 같은 5,000만 원이라도 퇴직금이 포함됐는지, 고정 초과근로수당이 들어 있는지, 목표 성과급을 미리 넣었는지에 따라 실제로 받는 돈이 달라집니다.

```bash
node salary-korea.mjs offer 52000000 --퇴직금포함 --고정OT 20
node salary-korea.mjs net 50000000 --식대 200000
```

### 채용절차법 위반 경고

공고나 지원서가 법이 금지한 항목(신체적 조건, 출신지역·혼인여부·재산, 가족의 학력·직업·재산)을 요구하면 알려 줍니다. 2024년 고용노동부 점검에서 629개소 중 220곳이 적발됐고, 직무 무관 개인정보 요구가 가장 많았습니다.

### 한국 공고 수집 (`providers/` 의 한국 모듈 일곱)

원본은 해외 채용 관리 시스템의 공개 JSON을 긁습니다. 한국에는 그 재료가 거의 없습니다. 공식 채용공고 RSS를 제공하는 플랫폼을 하나도 확인하지 못했고, 공개 API는 신청이나 계약을 거칩니다.

그래서 경로를 넷으로 폅니다.

1. 사용자가 붙여넣는 주소
2. 사용자 본인이 발급받은 공식 열쇠 (사람인 공개 API `saramin`)
3. 채용 포털의 공고 목록 — robots.txt가 허용한 범위에서
4. 기업 자체 채용 페이지와 국내 채용 관리 시스템

| 모듈 | 읽는 것 | robots 판정 (2026-08-21 실측) |
|---|---|---|
| `saramin` | 사람인 공개 API | 열쇠 필요. 하루 500회 |
| `saramin-web` | 사람인 공개 검색 결과 | `/zf_user/search/recruit` 허용 |
| `jobkorea` | 잡코리아 목록 탭 | `/recruit/joblist` 허용. `/Search/?stext=` 금지 |
| `jumpit` | 점핏 개발 직군 목록 | 화면 `/positions` 허용. API 호스트 robots 는 403 이라 못 받음 |
| `remember` | 리멤버 사이트맵 + 공고 상세 | `/job/`·사이트맵 허용. `/job_postings/` 금지 |
| `wanted` | 원티드 공고 API | robots.txt 가 403 이라 확인 불가. 기본값 꺼짐 |
| `greetinghr` | 그리팅을 쓰는 기업의 채용 페이지 | `Allow: /` |

**수집 방식에 넷을 겁니다.** 정체를 밝히는 사용자 에이전트를 쓰고, robots.txt를 보고, 원문 주소를 남기고, 재배포하지 않습니다.

이 넷은 판결이 정상적인 수집과 문제 된 수집을 가른 기준입니다. 잡코리아와 사람인 분쟁 1심(서울중앙지법 2015가합517982)은 "정체를 숨기고 출처를 지운 대량 복제", "가상사설망으로 주소를 분산하고 robots.txt를 보지 않은 채 긁은 것"을 문제 삼았고, 정체를 밝히고 원문으로 보내는 검색 로봇은 선별 허용된다고 봤습니다.

**두 판례가 실제로 다룬 것은 경쟁 서비스의 데이터베이스 침해입니다.** 잡코리아 대 사람인은 경쟁 채용 사이트가 남의 공고를 자기 사이트에 게재한 사건이고, 야놀자 대 여기어때는 경쟁 숙박 앱이 제휴 업소 정보를 자기 영업에 쓴 사건입니다. 개인이 자기 구직을 위해 공개된 공고를 읽고 자기 컴퓨터에만 두는 것과는 층위가 다릅니다.

**둘째 규칙은 코드가 집행합니다.** `providers/_robots.mjs`가 첫 요청 전에 robots.txt를 실제로 받아 파싱하고, 막힌 경로면 그 자리에서 멈춥니다. 문서에 적어 두는 것과 요청 전에 확인하는 것은 다릅니다.

**대상에서 뺀 곳**은 인크루트와 링크드인입니다. 둘 다 robots.txt로 모든 봇에게 전면 금지를 걸었습니다.

**원티드는 기본값이 꺼짐입니다.** 뺀 것이 아닙니다. 공고 API는 우리 사용자 에이전트에 200을 돌려주므로 첫째 규칙은 지킬 수 있습니다. 걸리는 것은 둘째입니다 — `robots.txt`가 403이라 파일을 받을 수 없고, 보관된 스냅샷(2026-01-08)에는 그 경로가 금지로 적혀 있으며, 오늘 파일이 그와 같은지는 확인할 방법이 없습니다. 도구가 대신 정하지 않고, `use_api: true`를 적은 사용자만 읽습니다. 파일을 받을 수 있게 되고 거기에 금지가 적혀 있으면 켜 두었더라도 멈춥니다.

수집한 공고는 사용자 컴퓨터 밖으로 나가지 않습니다.

## 그대로 살린 것

원본이 잘 만들어 둔 배관은 손대지 않았습니다.

- 지원 현황 추적 (병합·중복 제거·정규화·건전성 검사)
- 서류 PDF 생성과 사실 검증
- 자동 갱신기, 진단기, 플러그인 체계, 대시보드
- 시험 묶음 4,900여 건
- 공고 생존 확인, 반복 게시 탐지, 탈락 패턴 분석
- 사람이 최종 판단하고 클릭한다는 원칙

시장과 무관한 부분이고, 이 저장소의 실질적 자산입니다.

## 원본에서 왔지만 한국판이 보증하지 않는 것

지우지 않고 남겨 둔 것들입니다. 연결하지 않으면 돌아가지 않으므로 해가 없고, 해외 지원에는 쓸모가 있습니다. 다만 **한국 시장 기준으로 검증하지 않았고 앞으로도 하지 않습니다.**

- **국가 특화 공고 수집 모듈** — 독일 연방고용청, 폴란드·스페인·프랑스·덴마크·대만·동남아·중국 채용 사이트 등. `portals.yml` 에 적지 않으면 아무 일도 하지 않습니다
- **해외 채용 시스템 지원서 자동 채우기** (`prepare-application.mjs`) — 그린하우스·애쉬비·레버 폼용입니다. 국내 기업이 쓰는 시스템이 아닙니다
- **`modes/regional/eu-swe.md`** — 유럽 소프트웨어 엔지니어 규격입니다

이것들이 한국판 문서에 나오지 않는 이유가 이것입니다. 쓰고 싶으면 원본 문서를 참고하세요.

## 구조

```
modes/            한국 정본. 지시문은 한국어로 씁니다
modes/global/     해외·외국계 지원용. 원본 영어판 보존
docs/market-evidence.md   한국 시장 주장의 출처와 신뢰도 라벨

```

`modes/` 안의 머리글에서 `Block A`처럼 영어가 남아 있는 자리는 기계가 읽는 식별자입니다. 웹 보고서 화면이 그 글자로 절을 나눕니다. 원본의 일본어·힌디어판도 같은 관례를 씁니다.
